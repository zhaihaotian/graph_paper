## 1. Project Goal

Detect AI-generated academic papers via the **structural fingerprint of their introduction**, not via text-level cues. Concretely:

1. Parse each paper's Introduction into a typed argument graph (claims = nodes, logical relations = edges).
2. Compute graph-theoretic metrics on each.
3. Compare AI-generated vs human-written papers.

The corpus is FARS (suspected-AI papers from arXiv 2024–2026 cs.* submissions) + ICLR 2025 oral papers (human).

## 4. Schema (v2)

### 4.1 Node types (7)

| Type | Definition |
|---|---|
| **Context** | Field/problem framing. Includes "However X has issue Y" at the field level. |
| **Prior_Work** | Neutral description of what a specific prior method did. Subject is a named system/cited paper. |
| **Limitation** | Evaluative critique of a SPECIFIC named Prior_Work falling short. (Critical: NOT a generic field-level "However" — those stay Context.) |
| **Method** | The paper's proposed method or component. |
| **Result** | This paper's experimental outcome / number / ablation. |
| **Proof** | Pointer to in-paper supporting material (Figure, Table, Appendix). |
| **Contribution** | High-level claimed contribution. For benchmark/dataset papers, "Findings" → Contribution; for method papers, "Findings" → Result. |

**Subtypes** allowed via `Main: subtype` syntax (e.g., `Method: component`, `Contribution: Finding 1`, `Proof: experimental`).

### 4.2 Edge types (5 — strict whitelist)

| Kind | Required marker / condition |
|---|---|
| **elaboration** | (default fallback when no marker matches) |
| **contrast** | Marker required: However / Yet / But / Nevertheless / By contrast / Unlike / Instead / 然而 / 但是 / 反之 |
| **consequence** | Marker required: Therefore / As a result / Hence / Consequently / Thus / To address this / To this end / 因此 / 所以 / 为此 / 为了 |
| **evidence** | Target type must be `Result` or `Proof` |
| **addresses** | Cross-segment + both endpoints share a distinctive technical term (e.g., "diversity collapse", "calibrated signal"). Common words don't count. Direction: Method/Contribution → Limitation. |

**Retired edge kinds** (validator will reject): fork, join, critique, motivates, back_reference. Use the 5 above only.

### 4.3 Topology (computed, not authored)

- `fork` node: out_degree ≥ 2
- `join` node: in_degree ≥ 2

The renderer auto-detects and draws dashed grouping rectangles. JOIN boxes are suppressed when any two parents have an ancestor-descendant relationship (avoids "grandparent + descendant" repetition noise).

### 4.4 Special rules

- **Contribution outgoing edges**: ONLY two kinds allowed
  - `addresses` → Limitation (back-reference)
  - `elaboration` → another Contribution (parent → sub-claim hierarchy; e.g., "Contribution 3" → "3a/3b/3c")
  - All other outgoing kinds from Contribution are forbidden by validator.

- **Side-enum chip rendering**: A fork-parent's same-zone children that are ALL leaves (out_degree=0) AND have short display_labels (≤30 chars) AND parent zone is not Contribution → rendered as small chips on the right side of parent (not as full nodes below). Used for Context-level "harms include A, B, C" enumerations.

- **Sub-claim expansion**: When a single sentence enumerates parallel items, you MAY split into a parent node + lettered children (e.g., N4, N4a, N4b) connected by elaboration edges.

## 5. Critical Audit Rules (lessons learned the hard way)

These came from many rounds of reviewer-caught errors. Subagents will compress / mis-classify without them. Below grouped by **theme**, with the actual incidents that triggered each rule.

---

### 5.1 Context vs Limitation in para-1 ⭐ (the most common bug)

**Symptom**: Para-1 sentences with "However" labeled as Limitation when they should be Context. Reviewer mass-fix caught **~25 such mis-classifications** across the corpus.

**Concrete trigger** (from the conversation): User showed FA0001 para-1:
> "Large language models undergo extensive alignment training... However, fine-tuning causes broad misalignment... This emergent misalignment poses safety risks..."

I had labeled S2/S3 as Limitation. User said: this is Context — there's no specific Prior_Work being critiqued yet, the "However" is field-level problem framing, and the paper's whole topic IS emergent misalignment.

**Rule**: A Limitation requires a TARGET — a specific Prior_Work being critiqued. If "However" appears before any Prior_Work has been introduced, and it's framing a field-level problem, it's Context.

**Theme alignment heuristic** (added later): If the paper's title/abstract is about phenomenon X, and "However" introduces X → Context, not Limitation.
- Title "Defenses against EM" + "However EM exists" → Context (paper IS about EM)
- Title "Faster Sampling" + "However MCMC method M of Smith 2024 has variance V" → Limitation (specific named method critiqued)

**Fixed in**: SKILL.md Stage 2, expanded with examples. Stage 5 audit checklist has explicit Para-1 check.

---

### 5.2 Sentence coverage compression (the BIRD failure) ⭐

**Symptom**: Subagents reflexively compress dense methodology paragraphs (multiple "we propose / we use / we sample / we optimize" verb-clauses) into ONE summary node, silently dropping 5-10 sentences.

**Concrete trigger**: User pasted a translated paragraph from BIRD's Section 3 methodology, asked "is this in your SVG?" — I said "no, that's in §3 not intro". User pushed back: "I copied it from the introduction." I checked the PDF — they were right. **BIRD's intro has 4 paragraphs; I had skipped Para 3 entirely** (10 sentences containing abduction/deduction terminology, P(O|f) parameters, sampling+optimization, ∑ formula). Compressed into one summary node N12.

**Same bug found in coverage audit of other ICLR papers**:
- ICLR_KAN: dropped worked example formulas (3 sentences)
- ICLR_InferenceScaling: dropped DRAG/IterDRAG parallel paragraphs (6 sentences)
- ICLR_InfluenceFunctions: dropped GGN design-choice (1 sentence)

**Fix**: Built `coverage_check.py` — hard sentence-coverage validator that diffs source PDF intro sentences vs JSON node texts. **Threshold ≥85%. Fail = MUST add missing nodes.** Wired into SKILL.md Stage 5 as required.

**Pattern**: dense methodology paragraphs with formulas / parallel constructions / multiple "we X" verb-clauses are AT-RISK. Always run coverage_check on these.

---

### 5.3 OCR-broken anchor markdowns

**Symptom**: `anchor_intros_fixed/*.md` files have catastrophic OCR damage from two-column papers (column wrap mangled, sentences truncated mid-word). Earlier extractions used these markdowns and lost 30-70% of intro content.

**Concrete trigger**: User asked about FA0022_anchor's structure. I showed 8-node graph. User said "this looks too sparse." I checked the source PDF — the actual intro had 22+ sentences across 4 paragraphs. The markdown was truncated at "weight-tied recurrent co" mid-word. After re-extracting from PDF: FA0022_anchor went from **8 → 22 nodes** (+175%). FA0013_anchor went from **25 → 39 nodes** (+56%, recovered entire results+contributions block). FA0018_anchor went from **13 → 34 nodes** (+162%, recovered entire RL/RLVR/GRPO Prior_Work block).

**Fix**: ALL 11 anchor papers re-extracted from source PDFs via `pdftotext -layout`. Anchor markdowns are now **DEPRECATED — do not use**.

**Source PDFs**: `manual_review_workspace_2026-03-25/section_extractions/FA####_*/##_<title>.pdf` (the non-FA-prefixed PDF in each subdir is the anchor).

---

### 5.4 Edge kind marker discipline

**Symptom**: Subagents invent "(implicit)" connectives or label edges by semantic intuition rather than text marker. Reviewer caught: edges labeled `contrast` with no actual "However" / "But" / "Yet" in source; `consequence` without "Therefore"/"Thus".

**Rule**: Marker required for typed edge. **No marker → fall back to `elaboration`. Do NOT invent "(implicit)" connectives.**
- `contrast` markers: However / Yet / But / Nevertheless / By contrast / Unlike / Instead / 然而 / 但是 / 反之
- `consequence` markers: Therefore / As a result / Hence / Consequently / This raises / To address this / Thus / 因此 / 所以 / 为此 / 为了
- `evidence`: target node must be `Result` or `Proof`. Wrong target type → change to `elaboration` OR re-type the target.
- `addresses`: requires distinctive shared technical term. Common words ("training", "model", "method") DON'T count. If you have to squint to find the overlap, drop the edge.

**Fix**: Audit checklist in SKILL.md Stage 5 has 4 explicit marker checks.

---

### 5.5 Renderer routing & layout iterations

Lessons from ~5 SVG renderer revisions:

- **Citation dots originally above box** → got blocked by incoming arrows. Moved to right side (vertical stack outside box).
- **Box too short, only display_label visible** → expanded to show display_label + first 240 chars of verbatim text wrapped to 4 lines, dynamic height per row.
- **N3a/b/c "harms include credentials, malware, data leaks" originally placed below N3** → too noisy, broke main spine. Added **side-enum chip rule**: a fork-parent's same-zone children that are ALL leaves AND have short display_labels (≤30 chars) AND parent zone is NOT Contribution → render as small chips beside parent.
- **N3 → N4 edge "looked like coming from N3b"** in render: N3 was centered above N3b (its child). Edge from N3 bottom-center passed through N3b. Fixed by side-enum (children moved to side, edge no longer obstructed).
- **JOIN box label overlapping FORK box label** when same group is both forked-from and joined-to: staggered (fork label above the box, join label below).
- **JOIN boxes for "grandparent + descendant" parent sets created noise** (e.g., N6 → N7c AND N6b → N7c, where N6 is N6b's ancestor). Suppressed: skip JOIN box if any 2 parents have ancestor-descendant relationship.
- **Edge legend** added top-right to make 5 edge colors decodable without external reference.
- **Per-zone fork_labels**: a fork-parent with children in multiple zones (e.g., N6 → 4 Method-components AND N6 → 7 Findings) needs distinct labels per zone. Added `fork_labels: {Method: "...", Contribution: "..."}` field.

---

### 5.6 Contribution hierarchy (the NeuralODE 14-flat bug)

**Symptom**: ICLR_NeuralODE was extracted as 14 flat sibling Contribution nodes (numbered "1, 1b, 1c, 2, 2b, 2c, 3, 3b, 3c, 3d, 4, 4b, 4c, 4d"). User pointed out this should be **4 main contributions × ~3 sub-claims each**, not 14 flat siblings. Caused `max_width` metric to massively over-count (14 instead of 4).

**Original Contribution rule**: NO outgoing edges (flat list). This blocked sub-claim hierarchy.

**Fix**: Relaxed Contribution outgoing rule to allow `elaboration` → another Contribution (parent → sub-claim hierarchy). Added validator check: Contribution can only emit `addresses → Limitation` OR `elaboration → Contribution`. NeuralODE re-wired: 4 main + 10 sub-claim children with elaboration edges.

`max_width` redefined as "max **top-level** nodes per zone" (excluding sub-claims with same-zone in-edges). NeuralODE max_width went from 14 → 4.

**Side-enum rule** also patched: skip side-enum for Contribution zone (sub-claim contributions are substantial, render as full subrow nodes not tiny chips).

---

### 5.7 Schema collapse v1 → v2 (10 edges → 5)

Original schema had 10 edge kinds: elaboration, contrast, consequence, evidence, addresses + fork, join, critique, motivates, back_reference.

User pushed: "fork/join are topology, not edge labels. Compute them from out_degree/in_degree." Also: "critique is just contrast. motivates is just consequence. back_reference is just addresses."

Collapsed to 5: **elaboration, contrast, consequence, evidence, addresses**. Validator now rejects retired kinds with a redirect message. Old EXAMPLE.json (v1 schema) was kept briefly as a layout reference but kept causing confusion → eventually replaced with v2 FA0013 example.

---

### 5.8 Limitation scope: strict definition too sparse

User originally proposed: "for each Limitation L with **in_degree==1** AND that 1 parent IS Prior_Work, walk back through PW chain until you find a cited PW; record that PW's citations as the scope."

Implemented as specified — yielded **0.15 samples per paper** (most Limitations have in_degree=1 but parent is Context or another Limitation, not Prior_Work). Signal too weak.

Relaxed to: "for each Limitation L (any in_degree), reverse BFS, find nearest cited Prior_Work ancestor, record its citations." Yielded 2-4 samples per paper. Signal preserved (AI 1.12 vs Human 2.30).

---

### 5.9 Anchor flag unreliable

`anchor` is a manual boolean LLM flag. Some papers had `anchor_paper` metadata in JSON top-level but no node flagged with `anchor=true`; some had a flagged node but `anchor_paper: None` in metadata; some flagged nodes had 0 citations (giving 0 anchor_cite_share — meaningless).

User cut `anchor_cite_share` from final report. Lesson: **don't compute metrics that depend on subjective LLM flags**. Use citation-distribution proxies instead (single_cite_pw_share, pw_avg_cites).

---

### 5.10 Misc Python bugs found mid-build

- **f-string with `\n` inside `{...}` expression** → SyntaxError. Fixed by extracting to variable first.
- **Cycle in graph from `addresses` back-edges** → infinite recursion in `longest_from()`. Added cycle guard with `on_stack` set.
- **`anchor` field validation key** missing from compute_metrics output → CSV column missing → KeyError when summarizing. Fixed by ensuring all metric keys are in the cols list.

---

### 5.11 Paragraph-vs-type confusion (for sidebar zones)

User initially expected the SVG zones to mirror paragraphs (para-1 = top zone, etc.). The skill instead organizes by argumentative role (Context/PW/Limitation/Method/...). When user only saw the CONTEXT zone empty after N1, they thought we were dropping content — actually the other para-1 sentences were classified as Limitation and showed in the LIMITATION zone below the fold.

**Lesson**: explain "zones are by ROLE not by paragraph" early. SVG layout follows argument structure, not source-document layout.

## 7. Design Decisions Made

These are choices that affect interpretation and are worth knowing:

1. **`anchor_cite_share` was REMOVED** from the report — `anchor` was a manual LLM flag with inconsistent assignment across papers (some had `anchor_paper` metadata but no node flagged, vice versa). The user judged it too unreliable.

2. **`max_width` was redefined twice**:
   - Originally: max nodes per type-zone (raw)
   - Now: max **top-level** nodes per type-zone (excluding sub-claims that have a same-zone parent), so e.g., a Contribution row with "4 main + 10 sub-claims" reports width=4 not 14.

3. **Contribution hierarchy was added**: We allowed Contribution → Contribution `elaboration` edges (for parent → sub-claim hierarchy). Initially Contribution outgoing was banned entirely; relaxed in two stages.

4. **Limitation scope (C1) used relaxed BFS**: User's strict definition ("Limitation with in_degree=1 AND parent is Prior_Work") yielded only 0.15 samples per paper. Relaxed to "any Limitation, reverse BFS, find nearest cited PW ancestor" — 2-4 samples per paper, signal preserved.

5. **`avg_node_degree` → `sum_node_degree`**: User wanted total, not average. Equivalent to 2 × |edges|.

6. **Side-enum chips rule**: Only fires for Context-zone leaf children with short labels. Originally fired for any zone, made Contribution sub-claims look tiny — fixed.

7. **Edge legend was added** to SVG renderer (top-right corner) so colors are decodable without external reference.

## 8. Common Pitfalls for Future Work

If you're going to extend the corpus or refine metrics:

- **Subagent compression bias**: When extracting new graphs, ALWAYS run `coverage_check.py` before declaring done. Subagents naturally collapse 8-10-sentence methodology paragraphs into 1 node.

- **Para-1 "However" is NOT Limitation**: Even if it sounds critical. If no Prior_Work has been introduced yet, it's Context (problem framing).

- **`addresses` edges are easy to fake**: Require distinctive shared term. "training" / "model" / "method" don't count. If you have to squint, drop the edge.

- **Anchor flag is unreliable**: Don't compute metrics that depend on it. Use citation-distribution proxies instead.

- **Sub-claims should be hierarchical, not flat**: NeuralODE was extracted as 14 flat Contribution siblings; corrected to 4 main + 10 sub-claims with elaboration edges.

- **OCR for two-column papers**: Use `pdftotext -layout` first, then fall back to no-layout. Some papers (DeepSeekMath) are single-column and parse cleanly without `-layout`.
